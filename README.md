## `consistency` — ONE и QUORUM

| Уровень | Запись, мс | Чтение, мс |
|---|---|---|
| ONE | 456 | 2 |
| QUORUM | 517 | 2 |

n - число реплик r - число реплик с которых читаем и w - число реплик на которые пишем
по формуле r + w должно быть больше n чтобы у нас обязательно было пересечение между свежими r и w для гарантий чтения самых свежих данных
при ONE читаем и пишем на 1 реплику и они могут не совпасть 1 + 1 < 3, при QUORUM пишем и читаем минимум с половины 2 + 2 > 3 - хорошо

## `compaction` — TWCS и TTL

| Показатель | Значение |
|---|---|
| Стратегия компакции | TimeWindowCompactionStrategy, окно 1 DAY |
| default_time_to_live | 2592000 |
| События с TTL 5 секунд: до / после истечения | 5 / 0 |

- TWCS складываем файлы относительно  даты, а STCS смотрит просто на размер файла, поэтому несколько дней могут попасть в один файл и это не удобно для событий

- TTL показывает сколько должна жить записать а gc_grace_seconds показывает сколько должна жить пометка об удалении - чтобы другие реплики не восстановили запись как потеряную в случае если не удалили

- при удалении по ттл не нужно делать дополнительные записи на удаление - прставляют томбстоуны и записи изчезают при компакшене
